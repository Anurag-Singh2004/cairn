AI isolation should be tested, measured, and proven.

CAIRN (Cryptographic Assurance & Isolation for Red-Team Networks) is a security-testing harness that actively probes AI defense environments for leakage, checks fault handling, and produces cryptographically verifiable evidence.

01 / The approach

Make the security claim face a test.

CAIRN compares a deliberately leaky positive control against a hardened configuration. If the probes cannot catch known weaknesses in the baseline, their clean result cannot be trusted.

01

T0 · Leaky baseline

A deliberately weak reference setup with flat networking and shared storage. It checks whether the audit harness detects planted problems.

T1 · Hardened tier

Docker services use isolated internal networks, non-root execution, read-only root filesystems and restricted capabilities.

03 / Evidence & failure handling

Findings are backed by verifiable artifacts.

CAIRN is designed so reviewers do not need to trust a screenshot or a summary printed by the same process that performed the test.

Run the full demo locally
make demo

From the CAIRN repository root, with Docker available. The workflow runs the T0 and T1 reference tiers, fault injection, receipt verification and the tampering check.

Then inspect docs/RESULTS.md or verify a specific run using make verify RUN=<run-id>.

!

Scope and limitations — read this before interpreting the numbers

The committed reference runs use SimEngine, a deterministic simulated backend, not production LLM inference or real GPU execution. “NO_SIGNAL_AT_POWER” means no signal was detected under the stated sample sizes and inspected scope; it does not prove that all leakage is absent. Kernel exploits, physical hardware side channels and referee-key compromise are outside the stated scope. This Render page is a static, read-only showcase—not an online execution environment for the Docker-based assurance workflow.
